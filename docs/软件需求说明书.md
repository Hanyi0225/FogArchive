# 软件需求说明书 · 迷雾档案（FogArchive）

- 课程：鸿蒙高级应用开发工程师认证 · 期末大作业（主题一：校园线索推理与多结局探索 App）
- 作者：韩怡（学号 20230313238）· GitHub 账号 `Hanyi0225`
- 仓库：https://github.com/Hanyi0225/FogArchive
- 运行环境：DevEco Studio 5.0.13.230，HarmonyOS 5.0.5（API 17），Stage 模型，ArkTS + ArkUI

## 一、选题与背景

玩家以校刊学生记者身份，调查封楼五年的三号楼深夜亮灯事件。应用通过场景探索、线索收集、状态判定与最终指认推动剧情，线索与已掌握的关键状态共同决定后续节点能否进入，最终依据线索数量、指认对象与推论状态进入两个不同结局之一。本项目不接入在线服务器，剧情为本地静态配置，不要求 AI 生成剧情。

## 二、功能需求

### 2.1 选题硬性指标对照

| 选题要求 | 实现情况 |
| --- | --- |
| 至少 3 个可探索场景 | S1 一层大厅、S2 二层走廊（需 `gate` 门禁状态）、S3 校史馆档案室（需 `artificial` 推论状态） |
| 12 个有意义的事件节点 | N01—N12，节点含标题、热点描述、正文、进入条件、产出线索与产出状态 |
| 6 条可查阅线索 | C1—C6，线索板可查阅已掌握线索全文 |
| 线索与选择真实改变后续事件 | N08 需 C1+C3 交叉；N09、N12 需 `artificial`；N12 需线索 ≥4；状态与线索均参与判定，不是单纯文字跳转 |
| 2 个由不同条件触发的结局 | E1《迟到的合影》、E2《封楼的回声》，由 `DeductionService.judge` 计算 |
| 线索板、关键状态提示、阶段进度 | 线索板页面、节点缺项红字提示、首页与叙事页的阶段标识与线索/节点进度 |
| 存档与重开、中途结束进程后恢复 | RDB 三档位（1 号自动档 + 2、3 号手动档），Preferences 记录上次使用档位；杀进程后重开自动恢复 |

### 2.2 业务流程

接受调查 → 分场景搜集线索 → 满足条件后确认关键推论 → 进入推理台提交判断 → 依据证据链闭合情况进入对应结局；任意时刻退出应用，进度写入自动档，重新打开后恢复到上次场景与线索。

### 2.3 功能模块

1. **首页（Index）**：展示阶段、线索进度与节点进度，提供继续调查、新的调查入口。
2. **叙事场景页（Story）**：按场景页签展示节点卡片，区分「可调查」「已完成」「条件不足」三种状态，点击热点节点执行调查并产出线索/状态。
3. **线索板（ClueBoard）**：列出已掌握线索的标题与全文。
4. **推理台（Deduction）**：展示线索数量与推论状态，选择嫌疑人并提交判断，给出理由或结局。
5. **存档页（Archive）**：展示三档位摘要，支持手动存档、读档与清空。
6. **结局页（Ending）**：展示结局正文与重开、返回首页入口。

## 三、模块划分与交互关系

| 层 | 文件 | 职责 |
| --- | --- | --- |
| 入口层 | `entryability/EntryAbility.ets` | 应用启动时初始化 RDB、Preferences，并执行剧情配置自检 |
| 表现层（pages） | `Index / Story / ClueBoard / Deduction / Archive / Ending` | ArkUI 页面与组件，调用领域层方法，渲染状态与提示 |
| 领域层（domain） | `StoryEngine / ClueService / DeductionService / GameStore` | 节点进入判定、线索幂等收集、结局判定、全局游戏状态与节点执行 |
| 数据层（data） | `StoryData / SaveRepository / PrefsStore` | 剧情静态配置、RDB 存档读写、Preferences 偏好存储 |
| 模型层（model） | `Models.ets` | 线索、节点、存档快照及各类结果对象，纯数据承载，不依赖 UI |

交互关系：页面调用领域层；领域层读取模型与剧情配置，变更后由 `GameStore` 生成快照交数据层持久化；数据层读取结果经领域层校验后回填到全局状态，页面据此刷新。

## 四、数据模型

### 4.1 本地数据库（RDB）

数据库名 `fog.db`，安全等级 `S1`，表 `save_slot`：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `slot` | INTEGER PRIMARY KEY | 档位编号，1 为自动档，2、3 为手动档 |
| `version` | INTEGER NOT NULL | 存档结构版本，当前为 1 |
| `payload` | TEXT NOT NULL | 快照 JSON（`Snapshot.toJson()`） |
| `saved_at` | INTEGER NOT NULL | 存档时间戳 |

### 4.2 偏好存储（Preferences）

存储名 `fog_prefs`：

| 键 | 类型 | 说明 |
| --- | --- | --- |
| `lastSlot` | number | 上次使用的档位，默认 1 |
| `hintOn` | boolean | 是否开启阅读提示，默认 true |

### 4.3 领域对象（Models.ets）

| 类 | 主要字段 | 说明 |
| --- | --- | --- |
| `Clue` | id、title、sceneId、content | 一条线索 |
| `StoryNode` | id、sceneId、title、hotspot、body、hint、requireClues、requireFlags、addClues、addFlags、setPhase、minClues、action | 一个事件节点及其进入条件与产出 |
| `Snapshot` | version、phase、sceneId、visited、clueIds、flags、endingId、savedAt | 一次完整调查进度，可序列化为 JSON |
| `LoadResult` | snapshot、damaged、message | 存档读取结果，损坏时带标记与提示 |
| `ClueAddResult` | added、ids、message | 线索收集结果（是否新增、最新线索集合、提示） |
| `NodeResult` | ok、messages、needDeduce | 节点执行结果 |
| `SlotInfo` | slotId、empty、phase、clueCount、savedAt | 档位摘要，供存档页展示 |

## 七、测试方案

单元测试基于 hypium，位于 `entry/src/test/`，直接调用领域层纯函数，不启动 UI、不依赖真机传感器。共 8 条用例，覆盖正常、边界、异常三类：

| 类型 | 用例 | 验证点 |
| --- | --- | --- |
| 正常 | `normal_shouldEnterConditionNode` | 持有 C1+C3 时条件节点 N08 可进入并写入 `artificial` |
| 边界 | `boundary_deduceNeedFourClues` | N12 门槛 3 条不可进入、4 条恰好可进入 |
| 异常 | `exception_damagedSnapshot` | 损坏 JSON 与版本不匹配均回退空档并标记损坏 |
| 正常 | `normal_addClueIsIdempotent` | 重复收集同一线索不增加数量 |
| 异常 | `exception_endingGuard` | 线索不全或指认错误一律进入 E2 |
| 边界 | `boundary_canDeduceThreshold` | 推理台门槛为线索 ≥4 且需 `artificial`，缺一不可 |
| 正常 | `normal_judgeReasonListsGaps` | 分别返回线索缺口、指认不符、推论缺失与证据链闭合理由 |
| 正常 | `normal_blankSnapshotRoundTrip` | 空快照序列化后可无损往返恢复，不判为损坏档 |

## 八、验收方式

1. **剧情指标**：应用内可遍历 3 个场景、12 个节点、6 条线索，按规则进入 E1/E2 两个结局。
2. **规则生效**：线索或推论状态不足时，对应节点/推理台不可进入，并给出缺项提示；条件齐备后放行。
3. **持久化恢复**：完成若干节点后从最近任务列表结束应用进程，重新打开后场景、线索与节点进度恢复一致；重复收集的线索不重复计数。
4. **存档档位**：三档位可分别读写，损坏存档不导致应用崩溃，回退空档并提示。
5. **自动化测试**：在 DevEco Studio 中右键 `entry/src/test` 运行，8 条用例全部通过，覆盖正常、边界、异常三类。
6. **交付物**：仓库含源码、README（功能、开发环境、截图、运行方法）、本需求说明书与运行截图；GitHub 账号与仓库地址可在作业答案处填写。

## 九、已知限制

- 剧情为静态本地配置，不接在线服务；未接入音效与插图，界面为 ArkUI 排版。
- 指认对象为固定三人，未做自由文本输入。
- 本地单元测试覆盖领域层纯函数；RDB 读写需在设备/模拟器上按运行方法手动验证。
